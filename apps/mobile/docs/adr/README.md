# Architecture Decision Records

ADRs capture decisions that should outlive an implementation session. They are not progress reports or release notes.

Create an ADR for a decision about architecture boundaries, persistence, authentication, dependency strategy, navigation, caching, offline behavior, or future platform support. Name files with a zero-padded sequence and concise slug, such as `0001-android-first-target.md`.

```md
# ADR-NNNN: Title

**Status:** Proposed | Accepted | Superseded by ADR-NNNN

## Context

What durable problem or constraint requires a decision?

## Decision

What is the chosen approach and its boundary?

## Consequences

What becomes easier, harder, required, or explicitly out of scope?

## References

Roadmap release, source-of-truth API or web code, and related ADRs.
```
